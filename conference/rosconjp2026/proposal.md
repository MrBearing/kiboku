# サマリー
Kibokuは、ROS 1 / ROS 2 ワークスペースをROS環境非依存で静的解析し、パッケージ依存・外部依存・ルールベースのfindingsを抽出・可視化するRust製CLIツールです。本講演では、解析パイプラインとルールエンジンの設計、静的HTMLレポート生成の仕組み、およびワークスペース構造の把握での活用方法を紹介します。

# 提案内容

## 詳細: Kiboku: ROSワークスペースの静的解析と可視化

## 概要
本講演では、ROSワークスペース向け静的解析ツール Kiboku の設計と実装について紹介します。Kiboku は、Rustで実装されたCLIツール（バイナリ名: bok）で、package.xml を中心にワークスペース内のパッケージ構成と依存関係を抽出し、CLI 出力および静的 HTML レポートとして可視化します。実行時引数でプラットフォームを指定でき、catkin ベース・ament ベースいずれのワークスペースにも対応しています。

## 背景と課題
ROS を用いた開発では、ワークスペースが成長するにつれて全体像の把握が難しくなります。パッケージ間の依存関係は package.xml に記述されていますが、パッケージ数が増えると、ワークスペース内部の依存と外部ライブラリ依存が混ざり、どこが中核でどこが周辺なのかが見えにくくなります。結果として、「このパッケージは何に依存しているのか」「変更の影響範囲はどこまでか」といった判断が、個人の経験や grep に頼りがちになります。

既存のツール（colcon list、rospack、ament_lint 系など）はビルドや lint の文脈で有用ですが、ワークスペース全体の依存関係をまとめて可視化し、ルールに基づいて構成上の特徴を検出する用途には設計されていません。Kiboku はこのギャップを埋めることを目的としています。

## Kiboku の特徴
Kiboku の最大の特徴は、ROS の実行環境やインストールに依存せず、ファイル群そのものを静的に読み取る点です。手元に ROS が入っていない環境、CI、レビュー環境など、実行が難しい状況でもワークスペース構造の把握に使えます。

## アーキテクチャ
実装は、ワークスペーススキャナ、package.xml パーサ、TOML ベースのルールエンジン、レポート生成部から構成されています。解析で得られた情報に対して、プラットフォーム別の組み込みルールおよびカスタムルールを適用し、findings として抽出します。解析結果は JSON として出力でき、そこから単一 HTML またはディレクトリ形式の静的レポートを生成できます。レポートには、パッケージサマリー、ワークスペース内依存グラフ、外部依存グラフ、findings 一覧、findings マトリクスなどのセクションが含まれ、TOML 設定でセクションの表示順や可視性をカスタマイズできます。

パッケージ依存関係を横断的に把握・可視化する方法を学べる
自身のワークスペースに cargo install kiboku で即座に適用できるツールを持ち帰れる
現時点での限界と今後の展望
あわせて、現時点での限界と今後の改善点についても共有します。CMakeLists.txt 解析の追加、C++ / Python ソースコードからのノード・トピック情報の抽出、セマンティック解析の導入などは今後の発展余地です。これらを含め、Kiboku を ROS ワークスペース理解のための基盤としてどう発展させられるかを議論します。
